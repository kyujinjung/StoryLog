# StoryLog 앱 아이디어 정리

## 1. 앱 개요

가칭: **스토리 메모 앱**

책, 영화, 드라마, 웹툰처럼 긴 서사를 가진 콘텐츠를 감상할 때 등장인물, 사건, 관계, 용어, 진행 상황을 기록하고 다시 찾아볼 수 있는 앱이다.

사용자가 앞서 진행된 사건이나 인물 정보를 기억하지 못해 불편함을 느끼는 상황을 해결하는 것이 핵심 목적이다.

## 2. 핵심 문제

- 긴 작품을 보다가 이전 사건이나 인물이 기억나지 않는다.
- 위키나 커뮤니티를 검색하면 원치 않는 스포일러를 보게 된다.
- 인물 관계, 세력, 떡밥, 용어가 복잡한 작품은 일반 메모 앱으로 정리하기 어렵다.
- 내가 어디까지 봤는지 기준으로 안전하게 정보를 확인할 수 있는 도구가 부족하다.

## 3. 핵심 가치

**어디까지 봤는지 기준으로 스포일러 없이 인물, 사건, 관계, 떡밥을 기억해주는 스토리 전용 메모 앱.**

이 앱은 단순한 기록 앱이 아니라, 정보마다 작품 내 공개 시점을 붙여 사용자의 현재 감상 위치에 맞춰 보여주는 기억 보조 도구를 지향한다.

## 4. 주요 기능

### 4.1 작품 생성

사용자는 먼저 콘텐츠 단위로 작품을 생성한다.

예시:

- 소설 제목
- 영화 제목
- 드라마 제목
- 웹툰 제목
- 시리즈명

작품별로 아래 정보를 정리한다.

- 시대적 배경
- 세계관
- 장르
- 시즌 또는 권수 구조
- 회차 정보
- 원작 여부

### 4.2 인물 소개

작품에 등장하는 인물을 정리한다.

기본 정보:

- 사진
- 이름
- 별칭
- 가문
- 세력
- 직함
- MBTI
- 현재 진행 상황
- 첫 등장 시점
- 관련 사건

### 4.3 시점별 인물 상태

인물 정보는 고정된 프로필이 아니라 회차별로 변하는 상태로 관리한다.

예시:

- 1화: 왕실 기사단 소속
- 4화: 반역 혐의로 추방
- 8화: 북부 세력과 동맹
- 시즌 2: 실종 상태

이를 통해 사용자는 특정 회차 기준으로 해당 인물이 어떤 상태였는지 확인할 수 있다.

### 4.4 인물 관계도

등장인물 간 관계를 시각적으로 보여준다.

관계도 특징:

- 인물은 노드로 표시
- 관계는 선으로 표시
- 관계 유형에 따라 색상 또는 라벨 적용
- 특정 회차 기준으로 관계도 확인

관계 변화 예시:

- 1화: 동료
- 5화: 의심
- 9화: 적대
- 시즌 2: 혈연 관계 밝혀짐

### 4.5 줄거리 기록

시즌, 권, 회차 단위로 줄거리를 저장한다.

기록 단위:

- 시즌
- 권
- 장
- 회차
- 에피소드

### 4.6 사건 타임라인

줄거리와 별개로 큰 사건만 따로 정리한다.

예시:

- 전쟁 발발
- 왕 암살
- 주인공 일행 분열
- 특정 인물 사망
- 비밀 조직 등장

사용자는 "지난번에 무슨 일이 있었지?"라는 질문에 빠르게 답을 얻을 수 있다.

### 4.7 용어 정리

작품 속에서 새롭게 등장하거나 중요한 의미를 가진 단어를 저장한다.

예시:

- 세계관 고유 명사
- 마법 체계
- 조직명
- 지명
- 기술명
- 상징물
- 종족명

### 4.8 떡밥 및 복선 추적

추리, SF, 판타지, 드라마 장르에 특히 유용한 기능이다.

기록 대상:

- 수상한 대사
- 의미심장한 물건
- 아직 회수되지 않은 사건
- 정체가 불분명한 인물
- 반복 등장하는 상징

나중에 회수된 떡밥은 `해결됨` 상태로 변경할 수 있다.

### 4.9 헷갈리는 이름 및 별칭 관리

한 인물이 여러 이름으로 불리는 경우를 정리한다.

관리 항목:

- 본명
- 별명
- 가명
- 직함
- 가문명
- 한국어 번역명
- 원어명

예시:

- 아라곤
- 스트라이더
- 엘렛사르

### 4.10 세력, 가문, 조직 정리

인물만으로는 설명하기 어려운 작품의 구조를 정리한다.

예시:

- 왕국
- 가문
- 기업
- 종교 집단
- 반란군
- 행성
- 종족
- 학교
- 동아리
- 수사팀

각 세력별로 목표, 소속 인물, 적대 세력, 현재 상황을 정리한다.

### 4.11 이전 내용 빠른 복습

다음 회차를 보기 전에 이전 내용을 1분 안에 복습할 수 있는 기능이다.

예시:

`시즌 1, 6화를 보기 전 알아야 할 내용`

- A는 B를 의심 중
- C의 죽음은 아직 해결되지 않음
- 북부 세력이 왕실과 전쟁 준비 중
- 검은 반지는 3화부터 반복 등장

### 4.12 개인 메모와 공식 정보 분리

사용자의 추측과 확정 정보를 나누어 관리한다.

구분:

- 확정 정보
- 내 추측
- 의심되는 떡밥
- 나중에 확인할 것

추리물에서는 범인 후보, 알리바이 의심, 단서 해석 등을 기록하는 데 유용하다.

## 5. 스포일러 방지 기능

이 앱의 가장 중요한 차별점이다.

사용자가 현재 감상 위치를 설정하면, 그 이후의 정보는 자동으로 숨긴다.

예시:

- 현재 위치: 시즌 2, 4화까지 감상
- 시즌 2, 5화 이후 정보는 숨김
- 인물 설명도 현재 시점 기준으로만 표시
- 나중에 밝혀지는 정체나 관계는 잠금 처리

스포일러 방지는 기술보다 데이터 설계가 중요하다. 모든 정보에 작품 ID, 시즌, 회차, 공개 시점을 붙여야 한다.

## 6. AI 기능

AI는 사용자의 입력을 자동으로 보조하는 역할을 한다.

### 6.1 AI 자동 정리

사용자가 회차 메모나 줄거리를 입력하면 AI가 아래 후보를 추출한다.

- 인물
- 사건
- 용어
- 관계 변화
- 떡밥 후보
- 세력 정보

### 6.2 자연어 검색

일반 키워드 검색보다 자연어 검색이 잘 맞는 앱이다.

예시 질문:

- "주인공 도와줬던 안경 쓴 남자 누구지?"
- "시즌 1에서 죽은 왕 이름 뭐였지?"
- "검은 문양 처음 나온 게 몇 화였지?"
- "A랑 B가 왜 사이가 나빠졌지?"

### 6.3 AI 사용 원칙

처음부터 AI가 모든 내용을 자동 저장하게 만들기보다는, `AI 초안 + 사용자 승인` 구조가 안전하다.

초기 흐름:

1. 사용자가 회차 메모를 입력한다.
2. AI가 인물, 사건, 용어 후보를 추출한다.
3. 사용자가 확인 후 저장한다.

저작권 이슈를 피하기 위해 원문 전체 저장이나 공유는 조심해야 한다.

## 8. 작품별 커뮤니티

한 작품에 대해 여러 유저가 이야기를 나눌 수 있는 게시판 기능을 추가할 수 있다.

단순 게시판이 아니라, 작품별 집단 기억장치로 설계하면 차별점이 커진다.

### 8.1 커뮤니티를 넣는 이유

- 혼자 메모하기 귀찮은 정보를 다른 유저가 채워줄 수 있다.
- 인물 관계, 떡밥, 용어 정리가 더 빨리 쌓인다.
- 작품별 팬덤이 생기면 재방문 이유가 강해진다.
- "이 인물 누구였지?", "이 사건 몇 화였지?" 같은 질문이 자연스럽게 발생한다.

### 8.2 진행도 기반 게시판

게시판에서도 사용자의 현재 감상 위치를 기준으로 글을 보여준다.

예시:

- 소설: 3권 5장까지
- 드라마: 시즌 1, 6화까지
- 영화 시리즈: 2편까지
- 웹툰: 48화까지

게시글에는 스포일러 범위를 필수로 붙인다.

예시:

- 1화까지 스포
- 시즌 1 전체 스포
- 원작 결말 스포
- 영화판 스포
- 최신화 스포

사용자의 진행도보다 앞선 글은 자동으로 흐림 또는 잠금 처리한다.

### 8.3 게시판 카테고리

- 질문
- 해석
- 떡밥
- 인물
- 관계
- 오류 및 정정
- 감상
- 이론

### 8.4 앱 기능과 커뮤니티 연결

좋은 게시글은 개인 메모나 작품 DB에 반영할 수 있게 한다.

가능한 액션:

- 내 메모에 저장
- 인물 설명 후보로 제안
- 관계도에 반영 요청
- 떡밥으로 추가
- 용어정리에 추가

### 8.5 커뮤니티 주의점

게시판 기능은 관리 난이도를 높인다.

주의해야 할 요소:

- 스포일러 태그 미준수
- 원작 불법 공유
- 본문 복붙
- 욕설 및 분쟁
- 잘못된 정보
- 저작권 이미지 무단 업로드

초기에는 완전 자유 게시판보다 아래 수준으로 시작하는 것이 좋다.

1. 작품별 댓글 또는 질문 게시판
2. 게시글 작성 시 스포일러 범위 필수 선택
3. 사용자의 진행도보다 앞선 글 자동 숨김
4. 좋은 글을 개인 메모로 저장
5. 이후 정보 제안 및 공동 편집 기능 추가

커뮤니티 차별점 문장:

**내가 본 곳까지만 안전하게 이야기할 수 있는 작품별 스포일러 보호 커뮤니티.**

## 9. MVP 범위

처음부터 모든 기능을 만들기보다, 핵심 사용 흐름을 검증할 수 있는 기능부터 만든다.

1차 MVP:

1. 작품 생성
2. 현재 감상 위치 설정
3. 인물, 세력, 용어, 사건 기록
4. 회차별 줄거리 기록
5. 스포일러 방지
6. 인물 관계도
7. 이전 내용 빠른 복습

커뮤니티를 포함한 확장 MVP:

1. 작품별 댓글 또는 질문 게시판
2. 게시글 스포일러 범위 설정
3. 진행도 기반 게시글 숨김
4. 좋은 글을 개인 메모로 저장

## 10. 추천 기술 스택

### 10.1 추천 스택 1: 빠른 모바일 MVP

- 프런트/앱: React Native + Expo
- 백엔드: Supabase
- DB: PostgreSQL
- 인증: Supabase Auth
- 파일 저장: Supabase Storage
- AI 기능: OpenAI API
- 관계도 시각화: React Flow 또는 react-native-svg
- 배포: Expo EAS, App Store, Google Play

장점:

- 모바일 앱을 빠르게 만들기 좋다.
- 로그인, DB, 이미지 저장, 권한 관리가 Supabase에서 대부분 해결된다.

### 10.2 추천 스택 2: 웹앱부터 검증

- 프런트: Next.js
- UI: Tailwind CSS + shadcn/ui
- 백엔드: Next.js API Routes 또는 Supabase
- DB: Supabase PostgreSQL
- 관계도: React Flow
- 배포: Vercel
- AI: OpenAI API

장점:

- 앱스토어 출시 전 빠르게 검증할 수 있다.
- 관계도, 타임라인, 검색 UI를 만들기 편하다.
- 사용자 반응을 본 뒤 모바일 앱으로 확장하기 좋다.

### 10.3 최종 추천 1차 조합

처음 만들 때는 아래 조합을 추천한다.

- Next.js
- Supabase
- Tailwind CSS
- shadcn/ui
- React Flow
- OpenAI API
- Vercel

웹 MVP로 먼저 검증한 뒤, 실제 사용자가 복습, 인물 기억, 관계도 기능을 쓰는지 확인하고 React Native 앱으로 확장하는 방식이 현실적이다.

## 12. 데이터 구조 초안

스포일러 방지를 위해 정보마다 작품 ID와 공개 시점을 붙인다.

주요 테이블:

- `works`: 작품
- `episodes`: 시즌, 회차
- `characters`: 인물
- `character_states`: 회차별 인물 상태
- `factions`: 가문, 세력, 조직
- `relationships`: 인물 관계
- `relationship_changes`: 회차별 관계 변화
- `events`: 사건
- `terms`: 용어
- `foreshadows`: 떡밥, 복선
- `notes`: 개인 메모
- `user_progress`: 사용자별 감상 위치
- `posts`: 작품별 게시글
- `post_spoiler_ranges`: 게시글 스포일러 범위
- `comments`: 댓글
- `reports`: 신고

   - 책, 영화, 드라마 기록 앱으로 자연스럽고 확장성이 좋다.
2. **플롯로그**
   - 줄거리, 사건, 떡밥 추적 기능이 잘 드러난다.
3. **노스포 노트**
   - 스포일러 없는 기억 보조 앱이라는 차별점이 바로 보인다.
4. **서사노트**
   - 한국어 브랜드감이 있고 소설, 드라마, 영화 모두 품을 수 있다.
5. **스토리리콜**
   - 기억 안 나는 내용을 다시 떠올린다는 사용 이유가 잘 드러난다.

가장 무난하고 오래 갈 이름은 **스토리로그**다. 차별점을 강하게 밀고 싶다면 **노스포 노트**, 팬덤과 덕후 감성을 살리고 싶다면 **플롯로그**가 좋다.

9. 작품별 질문 게시판

## 16. 핵심 설계 원칙

- 이 앱은 단순히 정보를 저장하는 앱이 아니라, 정보마다 시점을 붙이는 앱이어야 한다.
- 모든 인물, 사건, 관계, 용어, 게시글에는 공개 시점이 있어야 한다.
- 사용자의 현재 감상 위치보다 앞선 정보는 숨겨야 한다.
- AI는 자동 저장보다 초안 생성과 정리 보조에 집중한다.
- 커뮤니티는 자유 게시판보다 스포일러 단계별 토론방에 가깝게 설계한다.
- MVP에서는 기능을 줄이고, 스포일러 없는 복습 경험을 먼저 검증한다.
